1Import and profile

You cannot fix what you cannot see. Five calls give you the whole picture.

import pandas as pd

2Handle missing values

Imputation is the last step. Normalising the vocabulary of missingness comes first.

2a. One representation of "missing"

df = df.replace(["NA","N/A","","Unknown","null","-","nan"], np.nan)

This file uses six different tokens for the same idea. Skip this line and "-" becomes a legitimate category — you will ship a model with a feature called dash.

2b. Which statistic for which column?

StrategyUse whenWatch out
Drop rows<5% missing, at random; or the target itself is missingBiases the sample if missingness is not random
MeanSymmetric numeric columnShifts under skew; shrinks variance
Median ✓Skewed numeric column (accident counts)Still invents a spike at one value
Mode / "Unknown"Categorical columnsOver-represents the majority class
Group-wise median ✓✓A related column predicts the missing oneNeeds a sensible grouping key
KNN / MICEMany correlated features, time to spareSlow; leaks if fitted outside the pipeline

Why median, not mean, in this dataset

ColumnMeanMedianGapSkew
accidents867351+147%4.56
deaths256102+151%4.21
driver_age_median42.536.9+15%13.2

When the mean sits 2–3× above the median, the distribution has a long right tail. Filling with the mean drags every missing row toward a handful of enormous states.

2c. Group-wise imputation — the same code, far less damage

# one global median: wrong, because a truck driver and a biker are different populations
df["driver_age_median"].fillna(df["driver_age_median"].median())

# median of each vehicle's own group: right
df["driver_age_median"] = df.groupby("vehicle_type")["driver_age_median"] \
                            .transform(lambda s: s.fillna(s.median()))

In this lab that group-by exposes a bug: it produced 8 groups for 6 vehicle types, because Two-wheeler and two wheeler were imputed separately. Lesson — tidy categories before you impute, not after.

The silent leak Using the median of the whole dataset means the test set helped choose the fill value. At prediction time you will not have the test set. Always impute inside a Pipeline.

3Encode categorical features

EncodingOutputUse for
One-hot ✓0/1 column per categoryNominal: road_type, weather, vehicle_type
Ordinal ✓One integer, explicit orderOrdered: Minor < Serious < Fatal
LabelOne integer, arbitrary orderTrees only, or very high cardinality
Target / meanCategory → mean of targetHigh cardinality, computed inside CV only
# ordered → explicit mapping (never LabelEncoder: it would sort alphabetically)
SEVERITY = {"Minor": 0, "Serious": 1, "Fatal": 2}
df["severity_code"] = df["severity"].map(SEVERITY)

# unordered → one-hot; drop_first kills the collinear dummy
df = pd.get_dummies(df, columns=["road_type","weather","vehicle_type"],
                    drop_first=True, dtype=int)
Why drop_first=True Keep all three dummies for a 3-level feature and NH + SH + Other = 1 always. Perfectly collinear columns make linear coefficients uninterpretable and can destabilise the fit. Trees don't care.

30 states ≠ 29 dummy columns. One-hot state and you add 29 mostly-empty columns — the curse of dimensionality on a 10k-row dataset. Label-encode it for tree models; target-encode it for linear ones, computed inside cross-validation.

Fix spellings before encoding, or encoding multiplies the damage "Two-wheeler" and "two wheeler" became two dummy columns, each trained on half the evidence. The fix is a lookup table (CANONICAL map), not cleverer regex.

4Normalise / standardise

ScalerFormulaOutputWhen

log1plog(1+x)unboundedHeavy right skew — fixes shape, not just scale
print(df["accidents"].skew())        # 4.56  → badly right-skewed
print(np.log1p(df["accidents"]).skew())  # 0.01  → symmetric

Two facts that separate juniors from practitioners

  • Tree models don't need scaling. They split on thresholds, and thresholds survive any monotone transform. In the lab, Random Forest scores 0.644 and Logistic Regression 0.640 — scaling bought no accuracy. It buys a correct optimiser.
  • Scaling exists because distances are unit-blind. With a raw feature on a 1–6 scale next to one in the thousands, the second dominates every Euclidean distance. After standardising, both get a fair say.

Read the two kinds of column separately. In speed_limit_kmph the fence (145) does catch the 999 codes and the 250 kmph typos — 330 rows — because they sit far outside a sane range. But in the count columns the same rule flags 10% of perfectly valid rows: those are the big states, not errors. A boxplot shows you the shape; only domain knowledge and a valid-range check tell you what is wrong.

The most expensive mistake in this notebook An outlier is not automatically an error. Deleting every row above Q3+1.5·IQR from accident counts deletes Tamil Nadu, Madhya Pradesh and Uttar Pradesh — the three states your road-safety study is about.

Delete what is impossible, clip what is merely extreme

# IMPOSSIBLE → delete the row (domain rules, not statistics)
VALID = {"speed_limit_kmph": (20, 120), "driver_age_median": (16, 80),
         "vehicles_involved": (1, 12)}
for col,(lo,hi) in VALID.items():
    df = df[df[col].between(lo, hi)]        # dropped 594 rows (5.8%)

# EXTREME BUT REAL → clip at the 1st/99th percentile (winsorise); no rows lost
for col in ["accidents","deaths","injuries"]:
    lo, hi = df[col].quantile([0.01, 0.99])
    df[col] = df[col].clip(lo, hi).round()

Put it together — the leak-free pipeline

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer

preprocess = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale",  StandardScaler())]), FEATURES_NUM),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                      ("encode", OneHotEncoder(handle_unknown="ignore",
                                               drop="first"))]), FEATURES_CAT),
])

model = Pipeline([("prep", preprocess), ("clf", LogisticRegression(max_iter=1000))])
model.fit(X_train, y_train)   # every median, scale and category learned here — from train only
model.predict(X_test)         # ...and merely applied here
Bonus: the pipeline is now cross-validatable cross_val_score(model, X, y, cv=5) refits the imputer, scaler and encoder inside each fold for you. Hand-cleaned dataframes cannot make that guarantee — which is exactly why production code is written this way.

Your practice drill

  1. Delete the two Step-2 cells that do global imputation and rebuild them inside the pipeline. Confirm accuracy barely moves while the leakage is gone.
  2. Add state as a label-encoded feature. Does it help a Random Forest? Does it help a Logistic Regression?
  3. Swap the median imputer for KNNImputer(n_neighbors=5) and compare the resulting distributions.
  4. Change the winsorising percentiles from 1/99 to 5/95 and re-read the boxplots. Where does real signal start disappearing?
  5. Replace the target with Fatal vs not and report precision/recall instead of accuracy. Why is that a better framing for road safety?
