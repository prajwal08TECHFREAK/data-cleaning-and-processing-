2Handle missing values using mean / median / imputation

First normalise the six different tokens that all mean "missing", then choose the statistic per column.

df = df.replace(["NA","N/A","","Unknown","null","-"], np.nan)   # one representation
df[c] = pd.to_numeric(df[c], errors="coerce")                   # un-trap the numbers
df = df.drop_duplicates().dropna(subset=["severity"])           # 205 rows gone
df[c] = df[c].fillna(df[c].median())                            # skewed counts → median
df[c] = df.groupby("vehicle_type")[c].transform(
            lambda x: x.fillna(x.median()))                     # driver age → group median
df[c] = df[c].fillna(df[c].mode()[0])                           # categoricals → mode

Why median and not mean?

Compare the two statistics before choosing. When the mean sits far above the median, the tail is long and the mean is a poor summary.

Decision Accidents, deaths and injuries are right-skewed (mean ≈ 2.5× the median), so they are filled with the median. Driver age is filled with the median of its own vehicle group, because a truck driver and a two-wheeler rider are different populations. Weather, cause and alcohol use are filled with the mode.

The variance telling you what imputation costs Raw variance is 4911.9. After mean-imputation it is 4444.6, after median 4447.3, after KNN 4444.6. Every method shrinks the spread — you are inventing data, and invented data is never as varied as real data. Mean and median produce a visible spike at one single value; KNN smears its guesses over the plausible range, which is why it looks smoother.

3Convert categorical features into numerical using encoding

Tidy the spellings first, otherwise encoding multiplies the damage.

# canonical lookup table, not clever regex
df["vehicle_type"] = df["vehicle_type"].replace({"two wheeler": "Two-Wheeler",
                                               "car/taxi/van": "Car / Taxi / Van"})
# ordered feature → ordinal mapping
df["severity_code"] = df["severity"].map({"Minor": 0, "Serious": 1, "Fatal": 2})
# unordered features → one-hot, drop_first kills the collinear dummy
df = pd.get_dummies(df, columns=NOMINAL, drop_first=True, dtype=int)
# high cardinality → integer codes (tree models only)
df["state_code"] = df["state"].astype("category").cat.codes

4Normalize / standardize the numerical features

Four scalers plus a log transform, applied to the same column so the difference is visible.

StandardScaler().fit_transform(X)   # (x - mean) / std      → mean 0, sd 1
MinMaxScaler().fit_transform(X)     # (x - min) / (max-min) → exactly [0, 1]
RobustScaler().fit_transform(X)     # (x - median) / IQR    → for outlier-heavy data
np.log1p(X)                         # compresses the tail — the only one that fixes SKEW

Fitting order The scaled columns shown here were fitted before Step 5 removed the impossible values, so a handful of extreme rows still influenced the mean and standard deviation. The script recomputes every scaler after outlier removal, which is the correct order: clean first, then fit the scaler on the cleaned data.
Skew: +4.56 before, +0.01 after log1p The three scalers leave the shape untouched — they only change the units on the axis. If your distribution is skewed, scaling does not fix it; the log transform does. For count data like accidents, deaths and injuries, log1p then standardise is the strongest combination.
Why scaling is not optional The distance between two sample rows is 16,604.00 in raw units and 11.18 after standardising. In the raw version the distance is essentially the difference in accidents alone — a feature measured in thousands drowns out one measured 1–31. Any distance-based model (kNN, SVM, k-means) would ignore the small features entirely. Tree models do not need scaling; linear models, kNN, SVM, PCA and neural nets do.

The trap in this table The IQR rule flags 1,004.0 rows (9.8%) in accidents — but those are Tamil Nadu, Madhya Pradesh and Uttar Pradesh, the large states your analysis is about. A z-score test is even worse here: it flags only 229 rows because the standard deviation is itself inflated by the skew. Neither rule can tell an error from a signal. That decision needs domain knowledge.

Domain rules decide the deletions: a speed limit of 999 kmph, an age of −1, a cluster with 31 vehicles. The extreme-but-real tail is winsorised — capped at the 1st/99th percentile — so the row survives with its other 30 columns intact. Deleting those rows instead would have thrown away 5% of the dataset for no good reason.

One thing this script cannot do for you Every statistic used above — medians, modes, scaler means, IQR fences — was computed on the whole dataset. That is correct for a cleaning report, and wrong for a model: at prediction time you will not have the test set. Wrap steps 2–4 in an sklearn Pipeline (SimpleImputer → StandardScaler for numeric, SimpleImputer → OneHotEncoder for categorical) and fit it on X_train only.
